# Music API (step 1, local) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A PHP REST API in `music-api/` that serves and edits the laptops' existing cloud folder (`library.json`, `playlists.json`, `songs/`), running locally under `php -S` and fully tested, ready to deploy to LWS unchanged.

**Architecture:** One `index.php` router (config, key, CORS, JSON errors) dispatching to small handlers in `music-api/lib/`. Storage = the two JSON files, read-modify-written under `flock` with temp-file + rename. Tests are Node (`node --test`) driving a real `php -S` against a folder the laptops' own Node code fills over the existing FTP test server, so compatibility is proven both ways.

**Tech Stack:** PHP 8.1+ (json, mbstring; intl optional), Apache `.htaccess`, Node test runner, `ftp-srv` fixture.

**Spec:** `docs/superpowers/specs/2026-11-24-music-api-design.md`

## Global Constraints

- PHP 8.1 syntax and functions only (tests run on PHP 8.1.34). No Composer, no framework.
- Required extensions: `json`, `mbstring` (startup check → 500 `{"error":"The server needs the PHP mbstring extension."}`). `intl` optional.
- Never keep a second library: only `<dataDir>/library.json`, `<dataDir>/playlists.json`, `<dataDir>/songs/`.
- Files written must match the laptops' format exactly (spec "The files"); unknown fields preserved; JSON written with `JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES`.
- Audio extensions: `.mp3 .m4a .opus .ogg .flac .wav`. `*.part.*` files are ignored.
- Key: header `X-API-Key` or query `key`, compared with `hash_equals`. Missing/wrong → 401 `{"error":"Missing or wrong API key."}`.
- CORS default origins: `https://localhost`, `http://localhost`, `capacitor://localhost`, `http://localhost:4200`.
- `updatedAt` = milliseconds since 1970 (`(int) round(microtime(true) * 1000)`).
- Song text limits: title required, title ≤ 200, artist ≤ 200, genre ≤ 60. Playlist name 1–100 chars after trim.

## Review Focus

- Non-ASCII titles (é, ç, emoji, Arabic) in keys, file names and URLs → same key as `lib.mjs`, file readable on Windows and Linux.
- A request for a song whose entry exists but whose file is gone → 404, never a PHP warning in the body.
- Range edge cases: `bytes=500-` (open end), `bytes=-100` (suffix), range past the end → 416 with `Content-Range: bytes */size`.
- An empty or missing `library.json` / `playlists.json` (fresh cloud) → empty lists, and the first write creates them in the laptops' format.
- A URL-encoded path trick (`/songs/..%2F..%2Fconfig.php/file`, `/songs/1abc/file`) → 404, never a file outside `songs/`.

## File Structure

| File | Responsibility |
|---|---|
| `music-api/index.php` | bootstrap: load config, checks, CORS, key, route table, dispatch, top-level error → JSON 500 |
| `music-api/router.php` | `php -S` router: real files under `music-api/` are never served; everything goes to `index.php` |
| `music-api/.htaccess` | Apache: deny `lib/`, `config*.php`, dot files; rewrite all else to `index.php` |
| `music-api/config.example.php` | returns the config array (committed); `config.php` (git-ignored) is the real one |
| `music-api/lib/http.php` | `json_out`, `fail` (throws `ApiError`), `read_json_body`, CORS, `send_file_range` |
| `music-api/lib/rules.php` | ports of `safeName`, `fileBase`, `trackKey`, `sameIdentity` |
| `music-api/lib/store.php` | `with_lock`, `read_library`, `write_library`, `read_playlists`, `write_playlists` |
| `music-api/lib/songs.php` | song handlers |
| `music-api/lib/playlists.php` | playlist handlers |
| `backend/tests/php-fixture.mjs` | find PHP, start `php -S` on a data folder with a generated config, `call()` helper |
| `backend/tests/music-api.test.mjs` | all API tests |
| `backend/tests/music-api-dev.mjs` | dev: persistent folder, seed, serve on `0.0.0.0:8000`, print key + curl list |

**Interfaces:**
- Consumes: Task 1 rules + fixture.
- Produces (PHP): `class ApiError extends Exception { public int $status; }`; `fail(int $status, string $message): never`; `json_out(mixed $data, int $status = 200): void`; `read_json_body(): array`; `with_lock(string $dataDir, callable $fn): mixed`; `read_library(string $dataDir): array` (default `['version'=>1,'nextId'=>1,'songs'=>[]]`); `write_library(string $dataDir, array $index): void`; `read_playlists(string $dataDir): array` (default `['version'=>1,'playlists'=>[]]`); `write_playlists(string $dataDir, array $doc): void`; `find_song(array $index, int $id): ?array`; route handlers take `(array $config, array $params)`.

- Routing: path = request path (decoded once) minus `dirname($_SERVER['SCRIPT_NAME'])`; ids match `^\d+$`, playlist uids `^[A-Za-z0-9-]{1,64}$`; anything else → 404 `{"error":"Not found."}`; known path, wrong method → 405 with `Allow`.

- [ ] **Step 1: Write the failing tests** (a `before` starts the FTP fixture and `startApi({ dataDir: join(ftp.root, 'music') })`; songs are added with the laptops' code: `withCloud(c => c.addSong(...))` + the MP3 file written into `songs/` from `makeMp3`):

  - `'a fresh cloud lists no songs and no playlists'` (empty data dir): `{ songs: [] }`, `{ playlists: [] }`.
  - `'no key or a wrong key is refused'`: 401 + error text for header-less, wrong header, wrong `?key=`; `?key=` right → 200.
  - `'the file streams whole and by range'`: full → 200, `Accept-Ranges: bytes`, `Content-Type: audio/mpeg`, body bytes equal the file; `Range: bytes=0-99` → 206, `Content-Range: bytes 0-99/<size>`, 100 bytes; `bytes=500-` → rest; `bytes=-100` → last 100; `bytes=<size>-` → 416 `Content-Range: bytes */<size>`; `HEAD` → headers, empty body.
  - `'unknown songs, missing files and path tricks are 404'`: `/songs/999/file`, entry whose file was deleted, `/songs/..%2F..%2Fconfig.php/file`, `/songs/1abc/file`, `/nothing`.
  - `'CORS preflight from the phone app'`: `OPTIONS /songs` with `Origin: https://localhost`, `Access-Control-Request-Headers: x-api-key` → 204, `Access-Control-Allow-Origin: https://localhost`, allow-headers contains `X-API-Key` and `Range`, no key needed; unknown origin → no allow-origin header. Normal responses to `https://localhost` carry `Access-Control-Allow-Origin` and `Access-Control-Expose-Headers: Content-Range, Content-Length, Accept-Ranges`.
  - `'a wrong method is 405'`: `PUT /songs` → 405.
